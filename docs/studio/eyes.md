# 眼睛系统:眼睛 / 眼位 / 眼神

本文是眼睛系统的唯一设计定义(2026-07-08 定案)。目标:**新角色几乎不需要任何眼睛调整**。

## 三层模型

| 层 | 是什么 | 存哪 | 谁改 |
| --- | --- | --- | --- |
| 眼睛(器官) | 统一嵌入式:眼白烤在 `base.png` 里,运行时只画瞳孔/眼皮 | 美术 + prompt 契约 | 生图阶段定死 |
| 眼位(容器) | 纯几何:每只眼在 base 图上的位置、大小、切线 | `rig.json` `gaze.eyes` | `tools/fit_eyes.py` 自动拟合;捏脸页仅作异常处理 |
| 眼神(表达) | 归一化的容器内表达:瞳孔、眼皮、画法、注视 | 眼睛模板(引用) | 改模板,全员受益 |

**数据只记录几何,不记录语义。**"怒眼""圆眼"是人对形状的解读,只允许出现在模板名和文档里,禁止作为 schema 字段(不要 `kind: 'angry'`)。工具需要展示分类时从几何推导(有切线 ≈ 怒眼)。

## 眼位:归一化局部坐标系

每只眼:

```jsonc
{
  "x": 0.147, "y": 0.534,          // 中心,相对 base 图(0..1)
  "radiusX": 0.06, "radiusY": 0.06, // 半径,分别相对图宽/图高
  "rotation": -0.04,                // 弧度
  "cuts": [ { "slope": 1.6, "offset": -0.42 } ]  // 0..n 条半平面切线;空数组 = 圆眼
}
```

定义**眼局部坐标系**:以 (x,y) 为原点、radiusX/radiusY 为单位、rotation 为轴向。容器 =
`|u| ≤ 1` **∩** 每条 cut 的 `u.y − slope·u.x − offset ≥ 0`。

- 左右眼各存各的 cuts(镜像写在数据里,渲染器无左右特判;对称由捏脸页镜像开关维护)。
- 未来新形状(方眼等)= 扩展几何词汇(更多 cuts 或新原语),仍然不引入语义字段。
- 嵌入式意味着眼位是**对美术的校准**:容器必须贴合 base 图里烤的眼白。`fit_eyes` 从图中拟合,QC 用 IoU 验证。

## 眼神:全部量以容器为单位

情绪预设中所有几何量都在眼局部坐标系里表达(瞳孔半径 = 容器的比例、shift = 局部单位、眼皮 = 临时切线)。因此**同一预设在任何角色的任何尺寸眼睛里几何成立**,这是模板可复用的根基。

**容器约束(不可穿模)**,双保险:

1. 钳位:容器按瞳孔半径向内收缩(椭圆钳 `|c| ≤ 1−ρ`,切线钳线距 ≥ ρ),瞳孔中心只在收缩域内移动 —— 眼珠贴边滑动不出眶。
2. 裁剪:瞳孔最终形状按容器边界裁剪 —— 任何极端参数下也只会贴满容器。

眼皮与眼位切线同构:怒眼 = 一条常驻切线,眼皮 = 情绪驱动的临时切线,同一套半平面数学。

## 眼睛 = 可复用资产(引用语义)

全项目**唯一一套**眼睛模板 `standard`(`src/characters/eyeEmotionTemplates.ts`,**手工设计的资产,不是生成物**;2026-07-08 从零重设计并完成模板合一)。

**为什么一套就够:瞳孔静息位 = 容器形心**。眼窝被切掉的区域会自动把形心(静息位)推离——泪滴眼窝的瞳孔天然坐得更低,新月眼窝天然贴下缘。因此表情不需要按眼窝形状做补偿位移,同一套表情在任何眼窝里几何成立。眼窝差异只活在眼位几何(cuts)里,这是"数据只记几何"的最终形态。

**标准状态目录**(语义固定;新状态必须先有行为触发场景才准进目录):

| 状态 | 语义 | 设计要点 |
| --- | --- | --- |
| default | 静息游荡 | 中性圆瞳(形心处) |
| aim | 追踪/瞄准 | **横向扁瞳**(0.46×0.30),小尺寸下可读 |
| alert | 受惊 | 瞳孔骤缩 |
| angry | 攻击性 | **斜切怒眉**(表达层切线,内深外浅)+ 瞳孔放大 |
| hit | 受击痛苦 | **X 眼**(经典卡通痛感) |
| scared | 恐慌/临爆 | 瞳孔放大 |
| dizzy | 眩晕 | 螺旋瞳 |

(focused 已删——无行为方使用且与 aim 语义重叠。)

行为映射约定:kaboomlet 临爆→`scared`,spooper 蓄力→`angry`,slime 跳跃→`alert`;不要为行为发明新状态名,先查目录。

rig.json 只存引用:

```jsonc
"emotions": { "template": "standard" }
```

- **角色默认零 override**——override 是逃生舱口,不是常规手段;出现 override 视为待收敛的债(workbench 表情预览会用 `*` 标出)。
- `pupilOffsetScale`(注视强度)统一设计默认 `{x: 0.28, y: 0.2}`,除非评审明确要求某角色不同。
- 改模板影响所有引用者;回归风险由 `studio:capture` 全量截图对比兜底。

评审面:workbench 总览页"眼睛模板"区在合成眼窝上渲染两套模板全状态(资产本体);每张角色卡的"表情预览"在真实 base 图上渲染同一套状态(几何来自 `src/render/eyes/eyeGeometry.ts`,与实机渲染共享,不会漂移)。对模板的意见走评审框(写入 review-inbox 的 `eye-templates` 条目)。

## 渲染:单一实现

所有角色共用一个 runtime 眼睛模块(容器数学、钳位、裁剪、瞳孔画法 dot/spiral/x、注视偏移)。各 kit 渲染器不得自带眼睛实现;行为状态 → 情绪名 的映射(蓄力→angry 等)留在各 kit,那是行为不是眼睛。

## 新角色眼睛流程(默认零手工)

1. 生图:prompt 契约保证实心纯白、闭合轮廓、不与其他白色区域粘连的眼白(见 `prompt-rules.md`)。
2. `tools/fit_eyes.py`:从 base.png 拟合眼位(椭圆 + 必要的切线)写入 rig.json;拟合置信度低则标记转人工。
3. rig 引用 round 或 cut 模板。
4. QC 数学验证:容器 vs 眼白 IoU ≥ 阈值;∀情绪 ∀注视方向 瞳孔 ⊆ 容器。
5. `studio:capture` 截图给人过目。

捏脸页定位:拟合失败的兜底 + 性格化微调(故意歪一点),不是必经工序。

## 无眼角色

刻意没有眼睛的角色(如 Hexbrim:巫帽+斗篷,帽下空无一物)在 rig.json 里**完全省略 `gaze` 段**——不要放空壳。QC 对无 gaze 的角色跳过全部眼睛检查;`fit_eyes` 不适用;情绪表达改走形变与外部特效(帽子倾斜、斗篷摆动、光效)。
