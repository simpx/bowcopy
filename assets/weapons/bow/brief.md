# Procedural Branch Bow

Role: Bowbert's runtime weapon attachment.

Visual target:
- Match the accepted branch bow direction from the prototype video references.
- Keep the bow as a procedural canvas/runtime attachment, not baked into Bowbert's body.
- Use the current Bowbert gameplay decision: no MVP charge requirement for firing, but the renderer can still preview draw states for future tuning.

Decomposition:
- runtime texture: generated by `src/render/player/proceduralBranchBow.ts`.
- placement: stored in this folder's `rig.json` and mirrored in `BOWBERT_BRANCH_BOW_TUNING`.
- arrow-on-string: drawn only during draw/aim preview, not as a permanent body asset.
- projectile arrow: runtime procedural projectile handled by `ArrowProjectileRenderer`.

Prompt packets:
- Target: procedural branch bow runtime texture
  - Inputs: `source/bow-relaxed-reference.png`, `source/bow-full-draw-reference.png`, `source/bow-aiming-reference.png`
  - Layer contract: bow attachment only; Bowbert body, eyes, released arrows, hit particles, and dodge VFX are runtime layers outside this asset.
  - Generation prompt: hand-drawn branch bow for a top-down doodle roguelike, curved brown wooden limb, green leaf tips, warm glowing bowstring, bold black outline, simple mobile-readable shape.
  - Boundary notes: keep the weapon independent from the player body. Show arrow only for draw-state preview.
  - Acceptance checks: readable at gameplay scale, matches the branch/leaf visual language, relaxed/full-draw/aiming states are previewable, transparent runtime texture bounds are stable.

Runtime evidence:
- `src/render/player/proceduralBranchBow.ts`: authoritative runtime draw code and tuning.
- `src/render/player/BowbertRenderer.ts`: places the bow around Bowbert and applies recoil/draw visual state.
- `assets/characters/bowbert/rig.json`: references the procedural bow as Bowbert's weapon attachment.
