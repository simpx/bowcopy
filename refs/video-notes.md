# Video Notes

这些笔记基于视频字幕和画面整理，内容是中文改写，不是完整逐字稿。后续实现时优先看 `systems-breakdown.md`。

## 00:00 - 00:21 Intro

视频展示了一个 72 小时 roguelike 原型：玩家操控拿弓的 goo 角色 Bowbert/Bobbit，在程序化地牢里清房间、打不同敌人、遇到巫师 NPC，并获得 power-up。作者强调这个项目的亮点是用简单系统快速制造内容量和手感。

## 00:21 - 01:04 Bow And Dodge

第一步是弓箭。鼠标按住时进入蓄力状态，角色和弓在几个拉弓帧之间切换；松开鼠标后发射箭。这个机制类似 Minecraft 的弓：按得越久，表现越明显。

为了让移动更有手感，作者加入空格翻滚。翻滚时角色快速移动，身后生成残影。箭矢飞行时，箭头位置有一个不可见圆形检测区，用来判断是否撞墙或命中怪物。

实现要点：

- 蓄力状态需要视觉反馈，而不是只改数值。
- 箭矢命中可以用小圆形碰撞体，不必做复杂像素碰撞。
- 翻滚残影是低成本高回报的反馈效果。

## 01:04 - 02:56 First Enemy Set

基础远程怪会找到玩家方向，加入一点随机偏角后移动一段距离，然后朝玩家发射飞镖。这个随机偏角让敌人看起来没那么机械。

三角变体复用同一套 AI，只改变血量和速度。它仍然朝玩家射击，但因为移动和生存时间不同，战斗体验会有差异。

蘑菇怪同样基于移动和射击循环，但发射的是会停留几秒的孢子。普通蘑菇发射四个菱形分布的孢子，紫色版本发射三个更危险的孢子。玩家可以用翻滚穿过它们。

实现要点：

- 先做一个可复用的远程敌人行为，再用参数生成变体。
- 静止危险物可以制造空间压力，迫使玩家移动。
- 翻滚需要和弹幕/危险区有明确关系，才能成为有意义的防御动作。

## 02:56 - 04:59 Procedural Animation

没有动画时，角色移动会像滑动贴图。作者用正弦波驱动 squash/stretch：改变 Y 轴缩放让角色上下压缩，再叠加轻微旋转，让 idle 和 walk 都有弹性。

不同状态使用不同动画 profile。走路状态提高频率和幅度，idle 状态较轻。敌人也复用这套系统，所以世界里的生物视觉风格统一。

角色眼睛会轻微朝鼠标方向偏移。做法是计算角色中心到鼠标位置的向量，然后限制偏移幅度。

实现要点：

- 用函数动画替代大量手绘帧。
- 同一套 squash/stretch 系统可用于玩家和敌人。
- 眼睛跟随鼠标是非常便宜的“活物感”细节。

## 04:59 - 07:36 More Enemies

史莱姆周期性跳向玩家，但跳跃方向不完全精准，也可能往反方向跳。这让它们更不可预测。大史莱姆死亡后分裂成三个小史莱姆；小史莱姆血量低、移动快，可以被翻滚直接撞掉。

炸弹怪会追逐玩家，距离够近后进入引爆状态，闪烁越来越快然后爆炸。玩家也可以用箭提前引爆。爆炸会检查范围内敌人并让它们死亡；对玩家则根据距离环判定伤害，越靠中心伤害越高。

幽灵怪会在房间中间附近短暂出现，向玩家方向发射三发弹体，然后快速消失。隐身阶段不可被箭命中。它不移动，但因为出现窗口很短，玩家要抓时机攻击。

实现要点：

- 敌人差异不一定来自复杂 AI，可以来自移动方式、攻击窗口和死亡效果。
- 炸弹怪既是威胁也是玩家可利用的战斗工具。
- 幽灵怪用“可命中窗口”制造不同节奏。

## 07:36 - 09:03 Sponsor Segment

这一段是 Odoo 赞助，不影响游戏实现。视频用项目管理类比 roguelike 里的随机事件和任务组织。

## 09:03 - 13:11 Dungeon Generation

作者没有做复杂算法，而是用简单像素地图/二维蓝图。中心黄色格是起始房间；白色格是普通战斗房；红色格预留 Boss 房；紫色格是巫师房。

生成时，每个像素/格子替换成一个房间模板。蓝图可以翻转、旋转，增加排列变化。新增房间类型只需要添加新颜色或新符号。

普通房如果只用一个模板会很重复，所以作者做了多个主题模板：木头房、石头房、蘑菇房等。每个主题有对应装饰物和敌人池。装饰物的位置会轻微随机偏移，并有概率水平翻转。

每个房间根据上下左右是否有邻居决定开口。墙体 sprite 会在开放和关闭状态之间切换。玩家进入房间后门关闭，清空敌人后门重新打开。

房间中心有隐形触发区，进入后敌人按刷怪点逐个出现，并伴随颜色区分的粒子。难度表决定该房间可能刷出的敌人、权重和总数量。更高难度会提高危险敌人出现概率，也会增加敌人数量，但暂时不直接提高敌人血量或伤害。

实现要点：

- 对小型 roguelike，模板化地图比复杂算法更可控。
- 像素图/二维数组是很好的关卡设计中间层。
- 房间类型、装饰、敌人池可以绑定，减少美术工作量。
- 难度优先调组合和数量，少直接堆数值。

## 13:11 - 14:37 Juice

作者强调 “juice”：让玩家知道动作产生了影响。多数动作都有轻微镜头震动，爆炸等大动作震动更强。

蓄力弓箭时，相机会轻微拉近角色，屏幕边缘变暗，制造发射前的期待感。箭撞墙、敌人射击、弹体拖尾、敌人生成和死亡都配粒子。生命 UI 平时轻微浮动，受击时闪白并抖动。

实现要点：

- 反馈系统要和动作强度挂钩。
- 镜头震动、缩放、暗角、粒子、UI 抖动都可以参数化。
- 没有 juice 时，玩法功能相同，但体感会明显变干。

## 14:37 - 15:46 Wizard Room

巫师房是特殊房间，通常放在走廊末端，像隐藏奖励点。房间里有蘑菇、树桩、坩埚和彩色粒子。玩家进入后，巫师会随机说一句话，有些偏励志，有些偏搞笑。

红色 Boss 房在视频中只是预留，作者承认时间不够，没有做完整 Boss。

实现要点：

- 特殊房间能打破连续清怪节奏。
- NPC 文本可做成简单数组随机抽取。
- 走廊末端适合放奖励、剧情或商店。

## 15:46 - 16:21 Scope

作者把项目限制在 72 小时开发量内。实际不是连续三天完成，而是分散到多天，每天约八小时，另外留出规划和修 bug 时间。时间限制让他避免无限加功能，也降低了项目失控的风险。

实现要点：

- 先完成可玩的闭环，再扩展内容。
- 时间盒能保护小项目，不让想法膨胀。

## 16:21 - 17:47 Silligils / Power-Ups

power-up 被称为 silly sigils/silligils。它们是 run 内成长，帮助玩家变强，也可能带一点代价。

视频中的示例：

- Triple Shot：一次射三箭，但射击冷却更长。
- Zoomsters：移动更快，但生命更少。
- Piercer：箭矢穿透敌人，但蓄力时移动很慢。
- Arrow Fringe：每次射击额外朝随机方向发一箭。
- Useless：什么都不做。
- Peaceful：提高房间不刷怪的概率。
- Silly Hatter：给角色随机帽子。

玩家可在巫师房看到三个随机 sigil，并组合出不同 build。作者提到未来可能借鉴 Hollow Knight charms，限制可装备数量。

实现要点：

- power-up 应改变行为，而不只是加攻击力。
- “增强 + 轻微缺点”能让选择更有张力。
- 装备槽限制可以防止无限堆叠。

## 17:47 - 18:24 Outro

作者计划未来可能加入 Boss、新敌人、新 sigil、新房间模板、更多世界观和打磨，再发布可玩版本。这个项目原本是一个短期小实验，但具备继续扩展的空间。
